# scrape: Firecrawl

The `scrape` stack runs a self-hosted [Firecrawl](https://github.com/firecrawl/firecrawl): a REST API that turns
web pages into clean Markdown, HTML, links or structured JSON for LLMs and scripts. It renders JavaScript with a
bundled headless Chromium, follows links to crawl whole sites, and can extract structured data with a local model
through Claude (Anthropic API) or a model on the host's Ollama.

| Service | Container | Local port | Tailnet URL |
|---|---|---|---|
| Firecrawl API and workers | `chi-firecrawl` | 3002 | `https://<TS_FQDN>:8011` |
| Playwright (headless Chromium) | `chi-firecrawl-playwright` | (internal) | |
| Redis, RabbitMQ, Postgres (job queue) | `chi-firecrawl-redis`, `chi-firecrawl-rabbitmq`, `chi-firecrawl-postgres` | (internal) | |
| LiteLLM gateway (only with `FIRECRAWL_MODEL`) | `chi-firecrawl-litellm` | (internal) | |

Approximate memory: 3 GB idle, more while crawling (the API is capped at 4 GB, Chromium at 2 GB, LiteLLM at 1 GB). Data: none;
the queue is disposable, so nothing is written to `DATA_DIR`. There is no web UI: `https://<TS_FQDN>:8011` only
answers with a short text.

## Enable

```bash
# .env: add scrape to CHI_STACKS
chi up scrape        # first run pulls about 3 GB of images
chi serve
```

Check it from any device on your tailnet:

```bash
curl -s https://<TS_FQDN>:8011/v1/scrape -H 'Content-Type: application/json' \
  -d '{"url": "https://example.com", "formats": ["markdown"]}'
```

## Use

The API is the same as the hosted Firecrawl ([API reference](https://docs.firecrawl.dev/api-reference/introduction)),
minus the features that need Firecrawl's cloud (Fire-engine anti-bot, billing, teams). The common endpoints:

| Endpoint | What it does |
|---|---|
| `POST /v1/scrape` | One page to Markdown / HTML / links / screenshot |
| `POST /v1/crawl`, `GET /v1/crawl/<id>` | Crawl a site (async); poll for results |
| `POST /v1/map` | List the URLs of a site quickly |
| `POST /v1/extract` | Structured JSON from pages with a prompt or schema (needs `FIRECRAWL_MODEL`; deprecated upstream in favour of a `json` format on `/v2/scrape`) |

The v2 endpoints (`/v2/...`) are available too. Structured extraction from one page, with `FIRECRAWL_MODEL` set:

```bash
curl -s https://<TS_FQDN>:8011/v2/scrape -H 'Content-Type: application/json' -d '{
  "url": "https://news.ycombinator.com",
  "formats": [{"type": "json", "prompt": "Top 3 stories",
               "schema": {"type": "object", "properties": {"stories": {"type": "array",
                 "items": {"type": "object", "properties": {"title": {"type": "string"}, "points": {"type": "number"}}}}}}}]
}'
```

Clients point at your server with an API URL; the API key is not checked, so any value works:

- Python SDK: `Firecrawl(api_key="fc-local", api_url="https://<TS_FQDN>:8011")`
- Node SDK: `new Firecrawl({ apiKey: "fc-local", apiUrl: "https://<TS_FQDN>:8011" })`
- MCP server for AI agents (Claude Code, Cursor and others):

  ```bash
  claude mcp add firecrawl -e FIRECRAWL_API_URL=https://<TS_FQDN>:8011 -e FIRECRAWL_API_KEY=fc-local \
    -- npx -y firecrawl-mcp
  ```

- n8n on the same machine: HTTP Request node to `http://host.docker.internal:3002/v1/scrape`.

## Configure

| `.env` key | Effect |
|---|---|
| `FIRECRAWL_MODEL` | Model for `/extract` and JSON formats. `claude-*` (e.g. `claude-opus-5-5`, or `claude-haiku-5-5` at a fraction of the price) uses the Anthropic API; any other name is an Ollama model on the host (e.g. `qwen3:8b`, `ollama pull` it first). Empty = AI features off. |
| `ANTHROPIC_API_KEY` | Anthropic API key; only needed for `claude-*` models. |
| `FIRECRAWL_VERSION` | Tag of the API image. Empty = `latest`. Set an exact build such as `2.11.616` to pin or roll back. |
| `FIRECRAWL_LLM_KEY` | Generated by `chi init`; the key between Firecrawl and the gateway. |

Run `chi up scrape` after changing any of them.

How AI calls are routed: Firecrawl only speaks the OpenAI API (mostly the Responses API, which neither Anthropic's
nor every Ollama version's compatibility layer covers fully), so with `FIRECRAWL_MODEL` set `chi up scrape` also
starts a [LiteLLM](https://github.com/BerriAI/litellm) gateway and points Firecrawl at it.
`stacks/scrape/litellm.yaml` routes `claude-*` to Anthropic and everything else to Ollama. Embeddings, used to rank
links when extracting from a whole site, always come from Ollama: run `ollama pull nomic-embed-text` once.
`stacks/scrape/pre-up.sh` warns when a model or key is missing.

Measured on a Mac mini M6 (16 GB): JSON extraction of one page took about 6 s with `claude-opus-5-5` and 20 s with
`qwen3:8b` on Ollama. Concurrency is set lower than upstream for a Mac mini
(`NUM_WORKERS_PER_QUEUE`, `CRAWL_CONCURRENT_REQUESTS`, `MAX_CONCURRENT_JOBS`, `BROWSER_POOL_SIZE` in
`stacks/scrape/compose.yaml`); raise them if you have memory to spare.

## Operate

```bash
chi logs scrape            # all services
chi logs scrape api        # just the API and workers
chi update                 # pulls new images
```

`chi backup run` stops the stack briefly like every other stack; there is nothing in it to back up. Jobs that
were queued at that moment are lost.

For monitoring, add an Uptime Kuma HTTP monitor for `http://host.docker.internal:3002/`.

## Troubleshoot

| Symptom | Check |
|---|---|
| `chi-firecrawl` restarts in a loop | `chi logs scrape api`. Usually RabbitMQ or Postgres was not healthy yet; it recovers by itself after a minute. |
| Pages come back empty or blocked | The site needs a real browser fingerprint or blocks datacenter traffic. Self-hosted Firecrawl has no Fire-engine; try `"waitFor": 3000` or a proxy (`PROXY_SERVER` in the compose file). |
| JSON output is `null` or `/extract` fails | `chi logs scrape litellm`. Usually `FIRECRAWL_MODEL` is empty, `ANTHROPIC_API_KEY` is missing or wrong for a `claude-*` model, or the Ollama model is not pulled (`ollama list`). |
| `chi-firecrawl-litellm` restarts in a loop | `FIRECRAWL_LLM_KEY` is empty or does not start with `sk-`. Run `chi init`, then `chi up scrape`. |
| Crawls are slow or Chromium runs out of memory | Lower the concurrency settings above, or raise `mem_limit` for `playwright-service`. |

## Security notes

The API has no authentication: upstream's API keys need a Supabase deployment. Access control is the tailnet,
like every other stack. Keep `BIND_ADDR=127.0.0.1`, do not route it through the `public` stack, and do not grant
guests `tcp:8011`. Anyone who can reach the API can make your server fetch arbitrary URLs, including addresses on
your LAN. With a `claude-*` model it can also spend your Anthropic credits: set a spend limit on the key in the
Anthropic Console. `ANTHROPIC_API_KEY` lives in `.env` like the other secrets and is backed up with it.
