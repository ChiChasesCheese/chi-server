## [1.0.0] - 2026-10-11

First public release as chi-server: an English, modular kit for running an Apple Silicon Mac mini (macOS 26+) as
an always-on home server.

### Added

- `bin/chi` single entry point with `init`, `bootstrap`, `unattended`, `doctor`, `remote-check`, `stacks`,
  `up`/`down`/`restart`/`ps`/`logs`, `update`, `serve`, `fetch`, `media`, `onboard`, `proxy`, `tv`, `backup`
  and `schedule`.
- Stack manifests (`stacks/<name>/stack.conf` with `DESCRIPTION` and `SERVE`): `chi stacks` lists stacks, and
  `chi serve` builds its port map from the manifests instead of a hard-coded table.
- Stacks: `core` (Homepage, Uptime Kuma, Dozzle), `ai` (Open WebUI with native Ollama), `automation` (n8n),
  `vault` (Vaultwarden), `photos` (Immich from upstream compose), `media` (Jellyfin, MeTube, subscriptions,
  IPTV), `public` (Cloudflare Tunnel on an isolated network).
- Provisioning: Homebrew bundle, server-grade macOS settings, OrbStack or Colima, Tailscale as a system daemon,
  Ollama; optional chezmoi dotfiles via `DOTFILES_REPO` / `DOTFILES_BRANCH`.
- Unattended mode: FileVault off, auto-login verified through `sysadminctl` and `/etc/kcpassword`, immediate
  screen lock and lock-at-login agent, Tailscale operator setup.
- Alerts: ntfy topic generated by `chi init`, `scripts/kuma-seed.sh` (interactive or non-interactive with
  `KUMA_PASSWORD_FILE`), healthchecks.io heartbeat via `HC_PING_URL`.
- Optional restic backups with consistent SQLite snapshots and online Immich database dumps.
- launchd schedules for backup, media cleanup, IPTV refresh and heartbeat.
- `chi remote-check` end-to-end check from a client machine; honours `CHI_REMOTE_DIR` and detects a legacy
  `~/chi-service` checkout.
- Split-routing proxy (mihomo) with PAC file, onboarding page for guests, Tailscale API helper for node sharing
  and grants (`scripts/friend-ts.sh`), guest macOS accounts for Screen Sharing (`scripts/friend-mac.sh`).
- Android TV management over adb (`chi tv`): sideload, proxy, always-on VPN.
- Documentation set: getting started, architecture with design decisions, configuration, CLI reference, one page
  per module, remote and guest access, operations, security, adding a stack, roadmap.
- MIT license, contributing guide, security policy, bats tests for `lib.sh`, CI with shellcheck and
  `docker compose config`.

### Changed

- All scripts, messages, templates and docs are in English.
- Personal settings removed from defaults: `TZ` is detected from the host, the dotfiles step is opt-in.

### Compatibility

- Legacy identifiers are kept so existing installs keep working: launchd labels `com.chi-service.*`, the log
  directory `~/Library/Logs/chi-service`, and `.env` keys and CLI subcommands are unchanged.
